# Trendsetter’s Second Brain

공부한 것을 기록하고, 프로젝트가 끝나면 회고를 남긴다. 이 저장소에서는 그 기록을 다시 읽고, 다음 기획에서 꺼내 쓸 지식으로 정리한다. **무엇을 알게 됐는지와 함께, 왜 생각이 바뀌었는지도 남긴다.**

이 소개는 원본과 이번 대화를 바탕으로 에이전트가 작성한 편집 초안이다. 사용자의 직접 인용과 해석은 아래에서 구분한다.

## 왜 기록을 남기는가

[하리보 회고](00_Raw/2026-07-12-%ED%95%98%EB%A6%AC%EB%B3%B4%20%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EB%B3%B5%EA%B8%B0.md)에는 “우리가 해결하려는 문제와 페르소나는?”이라는 질문이 있다. 팀의 논의가 기능으로 흐르는 데 답답함을 느끼지만, 곧 “저 페르소나도 내 중심이기는 했다”고 돌아본다. 마지막에는 자신의 의도를 더 명확히 전달했어야 했다는 반성이 남는다.

그래서 이 위키는 결론만 요약하는 것이 아닌, 나의 기대와 실제 나의 경험간의 차이, 설명이 통하지 않았던 순간, 다음에 바꿔볼 점도 회고 하기 위해 함께 둔다. 나의 second brain은 해당 회고와 이번 사용자 요청을 바탕으로 정한 운영 방향이다.

## 기록에서 지식으로

```text
원본 보존 → 내용과 발언자 확인 → 지식 정리·연결 → 질문과 기획에 재사용
                                  ↑                     ↓
                           실패·관점 변화·새 근거를 반영
```

- **에세이·독서**는 인용과 자기 생각을 나누고 망설임과 바람을 남긴다.
- **프로젝트·수업 회고**는 기대 → 실제 경험 → 판단 수정 → 다음 시도와 미해결 문제를 남긴다.
- **기술 글**은 에이전트 동작원리·질문·확인 과정을 중심으로 정리한다.
- **강의 필기·대화**는 강사의 주장, 자신의 생각, AI 답변을 구분한다.

예를 들어 [모루틴 후기](00_Raw/2026-07-13-%5BDraft%5D-%ED%83%88%EB%AA%A8%EA%B4%80%EB%A0%A8%20%ED%94%BC%EB%93%9C%20%EC%A0%9C%EA%B3%B5%20%EC%96%B4%ED%94%8C%2C%20%EB%AA%A8%EB%A3%A8%ED%8B%B4%20%EA%B8%B0%ED%9A%8D%20%ED%9B%84%EA%B8%B0.md)는 화면 구현에 만족하면서도 페르소나·신뢰할 정보·BM을 과제로 남겼다. 위키에서도 이를 검증 완료로 바꾸지 않는다. 자세한 [분류와 근거 규칙](20_Meta/Policy.md), [장르별 분석](10_Wiki/Topics/대표님-글쓰기-스타일-분석.md)을 따른다.

## 어디서부터 읽으면 되는가

[Wiki Index](20_Meta/Index.md)에서 관심 주제나 프로젝트를 찾고, 문서의 근거를 따라 원본으로 돌아간다. 개발·디지털 헬스케어·기획·콘텐츠·협업 기록을 다루며, Projects에는 진행 중 기획과 과거 회고가 함께 있다. 파일이 있다는 사실과 제품 구현·출시·검증 상태는 별개다.

Obsidian에서는 내부 `[[위키 링크]]`로 탐색할 수 있다. 이 README의 출처는 GitHub에서도 열 수 있는 상대 링크다.

## 시스템은 어디까지인가

현재 확인한 것은 Markdown 위키, 분류 정책, 인덱스와 관계 데이터, 수집 스크립트 및 작업 자산이다. 요청에 따라 에이전트가 정리하는 방식이며 실시간 감시·강화학습·자동 동기화의 실행은 확인하지 않았다. `.github/`에는 워크플로우가 없다.

P-Reinforce는 이 관리 방식의 이름이다. 과거의 임의 보상 가중치와 confidence 점수는 검증된 수학 모델이 아니므로 판단 기준에서 제외했다. [운영 지침](P-Reinforce_Skill.md)은 원본 근거와 관점 변화 보존에 집중한다.

[LLM-Wiki 원본 메모](00_Raw/2026-06-23-%5BDraft%5D-%5BKarpathy%5D%20LLM-wiki%20%EC%9D%B4%EB%A1%A0.md)에서 출발한 구조는 [Karpathy의 Gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)를 참고한다. Gist는 구현·성능 보증이 아닌 설계 제안이다. 현재 논의의 맹점, 참고 논문과 공식은 [연구 검토](20_Meta/Research-LLM-Wiki.md)에 따로 정리했다.

수정 이유와 미해결 내용은 [변경 기록](20_Meta/ChangeLog.md)에 남긴다. 원격 push는 사용자 검토·승인 후 수행한다.
