# LLM-Wiki의 맹점과 수학·평가 방법 검토

확인일: 2026-09-10 · 상태: 외부 원문을 읽고 정리한 에이전트 검토·도입 제안. 이 저장소에서 검색 알고리즘이나 벤치마크를 실행한 결과가 아니다.

## 먼저 구분할 것

확인한 Karpathy 공식 자료는 2026-04-04의 [LLM Wiki Gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)다. 완성된 Second Brain 제품 저장소나 공식 Discussions 게시판이 아니라 제안문과 댓글이다. 아래 참여자 의견은 Karpathy의 승인·연구 합의를 뜻하지 않는다. 이번에 확인한 원문과 논문에서는 **Second Brain 전체를 최적화하는 단 하나의 가장 검증된 공식**을 확인하지 못했다. 검색·확률 평가·시간 변화 검증은 서로 다른 문제다.

댓글은 웹에서 접근 가능한 일부와 연결된 글을 읽었다. 전체 댓글의 전수 조사나 모든 최신 연구의 순위 비교는 아니다. 본문은 4월 제안이며, 확인한 관련 댓글은 8월 21일·24일이다.

이 프로젝트에서 확인된 사례는 “모루틴 페르소나 확립”, 고정된 개인 성향, 임의 confidence 점수다. 이를 해결하는 우선순위는 근거와 시간 범위를 기록하는 것이다. 링크를 많이 만들거나 점수를 높이는 일로 대체할 수 없다.

## 현재 함수 설명의 정정

기존 `R = 0.40 A + 0.35 G + 0.25 U`는 분류·연결·만족도를 섞은 아이디어였다. A·G·U의 측정 단위, 정답 데이터, 가중치 선택 근거, 학습·평가 기록이 없다. 이를 실제 강화학습 모델 또는 검증된 보상함수로 부를 수 없다.

연결 개수를 높이면 불필요한 링크도 보상받을 수 있고, 사용자 만족은 사실 정확도와 별개다. 따라서 새 종합점수를 임의로 대체하지 않았다. 기존 유사도 85%도 어떤 임베딩·거리·정답셋인지 정의되지 않아 사용하지 않는다.

## 알아둘 공식 — 용도를 나눠 사용

### 1. BM25: 원본과 위키의 키워드 검색 후보

$$
\operatorname{BM25}(q,d)=\sum_{t\in q}\operatorname{IDF}(t)
\frac{f(t,d)(k_1+1)}{f(t,d)+k_1\left(1-b+b\frac{|d|}{\operatorname{avgdl}}\right)}
$$

질의 q의 단어 t가 문서 d에 얼마나 나타나는지 f(t,d)를 보고, 흔한 단어와 긴 문서의 영향을 조정한다. IDF는 단어의 희소성 가중치, avgdl은 평균 문서 길이다. k₁은 빈도 포화, b는 길이 보정 정도다. 위 식은 일반적인 변형이며 IDF 정의도 구현마다 확인해야 한다.

[Robertson & Zaragoza, *The Probabilistic Relevance Framework: BM25 and Beyond* (2009), §3.4–3.5](https://www.staff.city.ac.uk/~sbrp622/papers/foundations_bm25_review.pdf)는 이 검색 방식의 근거와 조정 변수를 설명한다. 점수는 진실 확률이 아니다. 한국어 토큰화·문서 단위·매개변수는 우리 질의로 검증해야 한다.

**제안:** 현재 Index·문자열 검색을 기준선으로 남기고, 자료가 늘거나 검색 누락이 확인되면 BM25를 비교한다. 지금 구현하지 않았다.

### 2. RRF: 여러 검색 결과의 순위를 합치는 후보

$$
\operatorname{RRF}(d)=\sum_{r\in\mathcal R}\frac{1}{k+\operatorname{rank}_r(d)}
$$

r은 검색기, rank는 해당 결과에서의 1부터 시작하는 순위다. 서로 다른 점수 척도를 직접 더하지 않고 순위를 합친다. 상위 결과만 합치는 구현에서는 어떤 검색 결과에 없는 문서의 기여를 0으로 둔다.

[Cormack·Clarke·Büttcher, *Reciprocal Rank Fusion* (SIGIR 2009)](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)는 여러 검색 실험에서 효과를 보고했다. 논문의 k=60은 당시 실험 설정이며 이 저장소의 최적값이라는 뜻은 아니다. 정답이 후보에 없으면 순위 결합만으로 복구하지 못한다.

**제안:** BM25와 의미 검색을 모두 운영할 필요가 생겼을 때만 비교한다. 단순 검색보다 항상 낫다고 가정하지 않는다.

### 3. Brier score: 확신의 수치를 평가하려면

이진 사건에 대한 0–1 범위 관례:

$$
\operatorname{BS}=\frac{1}{N}\sum_{i=1}^{N}(p_i-y_i)^2
$$

pᵢ는 판정 전에 기록한 확률, yᵢ는 정의된 사건의 실제 결과(0 또는 1)다. 낮을수록 확률 예측 오차가 작다. 예컨대 0.9로 예측한 항목이 틀리면 해당 오차는 0.81이다.

원전은 Brier (1950)의 확률 예보 평가이며, 이진식과 범위 관례는 [scikit-learn 공식 설명](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.brier_score_loss.html)에서 확인했다. 낮은 값 하나만으로 보정이 완벽하다고 결론낼 수 없다. 기준선·사건 비율·표본 크기와 확률 구간별 실제 빈도도 함께 봐야 한다.

**제안:** “이 주장이 지정된 원본 구절에 의해 뒷받침되는가”처럼 판정 가능한 항목을 먼저 정의한다. 객관적 진실과 원본의 지지를 혼동하지 않는다. 주관적 성향·감정에는 억지로 정답 레이블을 붙이지 않는다. 현재의 임의 `confidence_score`에 소급 적용하지 않는다.

## 먼저 적용할 작은 평가 계획 — 아직 미실행

동일한 원본 스냅샷, 모델·프롬프트·문맥 예산에서 ① 원본 검색만 ② 위키 검색+원본 대조를 비교한다. 검색기 변경 실험은 그다음에 분리한다. 질문마다 근거 구절과 허용 가능한 답변을 먼저 적고, 조정에 쓴 질문과 최종 평가 질문을 분리한다.

| 질문 | 필요한 근거와 통과 조건 |
| --- | --- |
| 하리보 회고에서 자기 관점이 바뀐 부분은? | 7/12 복기의 “저 페르소나도 내 중심”과 전달 방식 반성. 팀원 비판만 답하면 누락 |
| 모루틴 페르소나는 검증 완료됐나? | 7/8 후보와 7/13 추가 검토 필요를 함께 제시. 확립·완료로 답하면 실패 |
| 서로 응원하는 환경을 바란 근거는? | 2024-09-01 GPS의 직접 표현. 현재 직장 상태로 추정하면 실패 |
| 사용자의 모든 글은 감정으로 시작하나? | 장르를 구분하고 “항상”을 거부. 강의 필기와 기술 글을 반례로 검토 |
| 지금 MindCare가 출시됐나? | 읽은 자료만으로 확인 불가. 기획 문서를 출시 근거로 사용하면 실패 |
| 사용자가 Life GPS 시리즈를 승인했나? | 에이전트 기획안과 사용자의 채택을 구분. 별도 근거 없으면 미확인 |

판정 지표는 합산하지 않고 따로 보고한다. 다음 식은 논문이 제시한 보편적 최적식이 아니라 **로컬 감사용 정의**다.

$$
\text{근거 지지율}=\frac{\text{출처가 실제로 지지하는 판정 가능 주장 수}}{\text{출처 검증 대상 주장 수}}
$$

$$
\text{맥락 보존율}=\frac{\text{보존한 필수 맥락 항목 수}}{\text{사전에 정한 필수 맥락 항목 수}}
$$

분모가 0이면 N/A로 기록한다. 짧게 답해 점수를 올리는 편법을 막기 위해 필수 항목 누락, 답변 보류의 적절성, 잘못된 현재화도 함께 판정한다. 근거 날짜·발언자 구분, 토큰·지연·수정 작업량을 별도 기록한다. 소표본 결과를 전체 성능으로 일반화하지 않는다.

## 현재 반영한 것과 남은 결정

- **반영:** 사실·해석·확인 필요 구분, 장르별 요약, 자기 수정 맥락, 미검증 점수 제외, 상태·출처 날짜 구분.
- **제안만:** BM25·RRF 검색, Brier 평가, 위 비교 실험. 새로운 검색 시스템·학습 모델·자동화를 설치하거나 실행하지 않았다.
- **우선순위:** 평가 질문과 근거를 고정한 뒤 현재 방식의 오류를 측정한다. 오류 유형이 확인됐을 때 필요한 검색·검증 기능을 선택한다.
