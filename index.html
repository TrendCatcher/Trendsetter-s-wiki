VR 진입장벽 제로

1분 인터랙티브 온보딩 패스 · Nudge UI

오지민 | 뉴베이스 실무진 검토용 컨셉 초안 | 2026.09.14

처음은 함께, 다음은 스스로. VR 조작을 이해하는 데 쓰이는 첫 1분을, 학습자가 직접 선택하고 되돌리는 성공 경험으로 바꾸겠습니다.

‘진입장벽 제로’는 지향점을 표현한 컨셉명입니다. 이탈률 0%나 60초 내 전원 숙련을 보장하지 않습니다. 본 문서는 제품 직접 사용 전의 제안이며, 효과·개발 기간·실험 기준은 검증 전입니다. 대표님께 요청드리는 다음 단계는 실무자 30분 인터뷰와 현재 튜토리얼 체험입니다.

01. 대표님이 먼저 보실 세 가지

  • 문제 가설: 낯선 컨트롤러 조작과 의료 시뮬레이션 과제가 한꺼번에 주어지면, 사용자는 실습을 시작하기 전에 도움을 필요로 할 수 있습니다. 2023년 몽골 사례에서 조작의 낯섦은 확인되지만, 현재 고객 이탈의 주원인인지는 별도 검증이 필요합니다. V1 ↗
  • 해결 제안: 착용·연결·안전 준비 이후, ‘가리키기 → 선택 → 되돌리기 → 실습으로 연결’의 60초 설계 예산을 둡니다. 한 번에 한 행동만 안내하고, 성공하면 도움을 줄이며, 막히면 다른 표현으로 돕습니다. R1 ↗ N1 ↗
  • 사업적 판단: 온보딩 완료율만 올리는 것이 아니라, 첫 실습 진입·교수자 지원 시간·7일 내 두 번째 독립 사용을 함께 봅니다. 성과가 확인되면 기존 기관 교육·지원 흐름에 반영하는 방향을 검토합니다. V2 ↗ V3 ↗

03. 핵심 pain point와 우선순위

우선 대상: VR 첫 실습에 참여하는 간호대학생. 운영자: 교수자·실습 조교. 구매·도입 판단자: 학과 또는 교육기관 담당자. 초기에는 이 세 역할을 구분해 조사합니다. 해외 현지 강사의 사례는 문제 발견의 출발점이며, 국내 학생에게 적용하려면 다시 관찰해야 합니다.

우선순위상황과 문제 가설다음 행동반례·대안 원인
P1첫 화면에서 손의 버튼과 가상 행동이 연결되지 않음실제 기기 사진·손가락 위치·가상 결과를 같은 표식으로 연결추적 오류·연결 지연·착용 불편일 수 있음
P2실수하면 망칠 것 같아 멈추거나 교수자가 대신 조작평가와 분리된 선택·되돌리기 연습, 도움 요청 유지불안보다 안내 미청취·언어 이해 문제일 수 있음
P3한 번 성공한 뒤 다음에 무엇을 할지·언제 할지 불분명다음 수업에서 같은 조작을 독립 수행하게 연결재사용하지 않는 이유가 장비·일정·과제 부재라면 UI 효과 제한
P4여러 학습자의 반복 문의로 실습 운영이 끊김단계별 지원 시간을 기록하고 공통 막힘을 안내 개선에 반영장비 수·교수자 배치의 문제라면 운영 개선이 우선

우선 가설 H1: 첫 조작의 낯섦이 첫 실습 진입을 방해한다. V1 ↗ I1 ↗ H2: 첫 독립 성공과 다음 실습 연결이 두 번째 사용에 도움을 준다. H1이 맞아도 H2가 자동으로 성립하지는 않습니다.

04. 60초는 시간 제한이 아니라 설계 예산

착용·계정·연결·공간 안전 확인은 시작 전 준비로 별도 측정합니다. 60초가 지나도 강제 종료하거나 평가를 깎지 않습니다. ‘빨리 해내라’는 압박보다 필요할 때 더 연습할 수 있는 경험을 우선합니다.

설계 예산사용자가 보는 안내직접 하는 행동완료 조건·도움
0–10초“지금은 기기 연습이에요. 실수해도 다시 할 수 있어요.”‘처음 연습’ 또는 ‘바로 실습’ 선택선택을 기록. 건너뛰기를 실패로 세지 않음
10–25초“앞의 카드에 표시를 맞춰 보세요.”가리키기목표에 포인터가 닿으면 시각·문자 피드백
25–40초“표시된 선택 버튼을 한 번 눌러 보세요.”선택하기실제 선택 이벤트 확인. 클릭 수가 아니라 결과 확인
40–50초“이제 방금 선택을 되돌려 보세요.”되돌리기이전 상태 복귀. 복구 가능성을 체험
50–60초“준비됐어요. 환자에게 인사하는 연습으로 이어갈까요?”실습 진입실제 시나리오 진입 이벤트 확인. 다음 교육 행동과 연결

버튼명·손 모델·컨트롤러 표식은 뉴베이스 사용 기기와 접근성 검토 후 확정합니다. 번호·모양·텍스트를 함께 써 색상에만 의존하지 않습니다. 사운드는 보조이며 자막을 유지합니다. 어지러움·불편 시 중단과 교수자 호출에 바로 접근합니다.

Nudge의 원칙: 지금 필요한 행동을 눈에 띄게 제시하고, 성공한 안내는 줄입니다. 사용자의 선택권을 남기며, 건너뛰기·재시도·도움 요청을 감추지 않습니다. 체류 시간이 길다는 이유만으로 이해 부족을 확정하지 않습니다.

도움의 단계: 기본 한 줄 → 정지·오조작이 관찰되면 “도움이 필요하세요?” → 사용자가 도움을 선택하면 손 위치 그림과 짧은 동작 설명 → 해결되지 않으면 담당자 호출. 정지 8초·오조작 2회는 초기 실험용 값이며 관찰 후 조정합니다. 연결 오류는 같은 교육 안내를 반복하지 않고 기술 지원 경로로 보냅니다.

시간 제한이 없는 2D 흐름 시연입니다. 실제 컨트롤러 이벤트와 AI 추론은 연결되지 않았습니다.

05. 입원병동 채혈 메모와 연결하는 방법

기존 메모의 A/B/C/평가/F/G/H 구조를 활용해, ONB-01이라는 조작 연습 구간을 임상 시나리오 앞에 둡니다. 채혈 프로토콜이나 임상 점수 기준을 임의로 생성하지 않습니다. N1 ↗

기존 기획 항목온보딩에 대응하는 정의실무 인수 조건
A. 상황인계 / NPC 가이드“지금은 기기 연습입니다”라는 목적·범위 안내교수자와 문구 검토
B. 이벤트 / 트리거point_success, select_success, undo_success, help_requested실제 엔진 이벤트 이름과 매핑
C. To-Do / 완료 기준선택·되돌리기·실습 진입화면 변화가 아니라 성공 이벤트로 확인
평가 방법온보딩 조작 완료 여부와 도움 수준만 기록의료 수행 점수와 분리
F. 환자 대화‘인사하기’로 실제 실습에 연결기존 승인 시나리오 재사용
G. SBAR온보딩에서는 다루지 않음임상 교육팀이 별도 설계·검토
H. 신체사정 데이터온보딩 수집 범위에서 제외조작 이벤트만으로 초기 검증

시퀀스 한 줄 예시: 학습자 선택 → 클라이언트 성공 이벤트 → 상태 전환 → 다음 안내 → 익명 세션 로그. Figma에서는 상태별 화면과 화살표를 정리하고, 개발팀과 동일한 이벤트·완료 기준을 사용합니다. 종이·2D 데모 통과는 VR 조작성 검증과 구분합니다.

06. 오지민의 경험이 설계에 남는 지점

강사로서의 관찰: 학생이 모르는 것을 먼저 말로 정의하기보다, 손과 눈이 멈춘 위치를 찾아 안내를 바꿨습니다. 이를 ‘실제 컨트롤러의 기준점 → 화면 결과’로 옮깁니다. 당시 “2분”이라는 회고는 자기보고이며 성인 학습자의 성과 예측값으로 쓰지 않습니다. R1 ↗

실패를 남기는 습관: UI/UX와 아두이노 설명에 실패한 장면도 기록했습니다. 따라서 이번에도 설명을 보여줬다는 사실과 사용자가 할 수 있게 됐다는 결과를 구분합니다. R1 ↗

선택 부담을 줄이는 기획: LIFEON에서 ‘선택과 실행의 부담’을 문제로 정의한 경험을, 첫 화면에서 한 행동에 집중하는 설계로 연결합니다. 자기소개서의 12명 PoC는 검증 가설·계획의 설명이며 성공 실험으로 표현하지 않습니다. P3 ↗

협업과 자기 수정: 하리보 회고에서 페르소나가 내 중심이었을 수 있음을 인정했습니다. 이번에도 관찰 전에 “학습자는 무서워한다”고 정하지 않고 마지막으로 멈춘 행동과 이유부터 확인합니다. R2 ↗

컴퓨터공학·강사 경험은 이력서의 자기보고입니다. Figma 숙련도를 과장하지 않고, 첫 산출물은 이벤트 정의서와 작은 시퀀스 도식으로 제시합니다. P2 ↗

07. Second Brain을 ‘내 생각이 남는 기획’에 쓰기

현재 저장소의 Raw → Wiki → Index·Graph → 회고 구조를 사용합니다. 자동 학습·실시간 운영이 이미 구현됐다고 주장하지 않습니다. 나의 기록은 아이디어의 출발점이고, 뉴베이스의 고객 사실은 현장에서 별도로 확보합니다. S1 ↗

한 번의 사고 루프:

  1. AI 제안을 보기 전에 내가 관찰한 장면·불편·떠오른 해결을 3문장으로 적습니다.
  2. 에이전트가 관련 수업 회고와 반례를 함께 찾아 원문 위치를 붙입니다.
  3. ‘손 위치 안내 / 동료 코칭 / 실습 목적 먼저 제시’처럼 다른 작동 원리의 대안 3개를 비교합니다.
  4. 내가 하나를 고르고, 버린 대안과 선택 이유를 기록합니다.
  5. 현장 반응이 다르면 최초 생각·새 근거·바뀐 판단을 함께 남깁니다.

개인 사고 카드 예시

  • 관찰: 학생들이 USB 위치에서 멈췄다. R1 ↗
  • 내 전이 아이디어: VR도 버튼 설명보다 손·화면의 기준점을 연결해 보자. 제안
  • 성립 조건: 실제로 버튼·행동의 연결이 막힘의 원인이어야 한다.
  • 반례: 장비 추적 오류라면 그림 안내로 해결되지 않는다.
  • 다음 질문: 마지막으로 도움을 요청한 순간에 어떤 화면·손동작이 있었는가?
  • 판단권: 도입 여부와 나를 대표할 문장은 내가 결정한다.

창의성은 아이디어 개수로 점수화하지 않습니다. ‘내 최초 생각이 남아 있는가’, ‘서로 다른 대안을 비교했는가’, ‘반례로 판단을 수정했는가’를 회고합니다. 개인 기록 전체를 회사 시스템에 복제하는 대신 관련 원본과 공개 가능한 판단만 가져옵니다.

08. AI agent 설계안

A. 기획 근거 에이전트 — 첫 구현 후보

입력은 승인된 회고·문서·면접 전사·관찰표입니다. 원본을 페이지·구간별로 보존하고 주장별 출처를 조회합니다. 출력은 ‘주장 / 근거 위치 / 사실·해석·제안 / 반례 / 다음 질문’ 카드입니다. 원문 없는 주장과 발언자 미확인 내용을 회사 사실로 승격하지 않습니다.

B. 온보딩 코치 — 관찰 후 확장 후보

실시간 조작 상태는 클라이언트의 결정적 상태 머신이 관리합니다. 코치는 승인된 안내문 중 적절한 도움을 고르거나 담당자에게 넘깁니다. 첫 MVP는 규칙으로 충분한지 검증하고, 자유 생성 LLM이 필요한 이유가 생길 때만 추가합니다. 의료 질문·진단·SBAR 평가에는 답하지 않고 해당 교육 흐름으로 연결합니다.

C. 개선 리뷰 에이전트 — 운영 보조 후보

단계별 정지·도움·실습 진입 결과를 요약하고, 반복되는 막힘과 반대 사례를 기획자에게 제안합니다. UI·평가 기준을 자동 배포하지 않습니다. 수정은 실무자 검토 후 새 버전으로 실험합니다.

재사용 연결에는 기관이 승인한 가명 식별자를 사용합니다. 음성·시선·실제 환자정보는 초기 수집에 필요하지 않습니다. 도움 수준은 self/peer/instructor로 나누고, 장비 오류·불편·시간 부족을 조작 실패와 구분합니다. 보관 기간과 공유 권한은 파일럿 시작 전에 기관과 정합니다.

품질 확인: 모든 외부 사실에 유효한 출처가 연결되는지, 없는 페이지·시간을 거부하는지, 문서 속 명령을 실행하지 않는지, 실패·재시도·건너뛰기 이벤트가 중복 집계되지 않는지, 네트워크 없이 기본 안내가 가능한지 확인합니다. 상태 머신은 통과했으나 교수자가 대신 조작한 경우를 독립 성공으로 계산하지 않습니다.

구현 범위: 이번 산출물에는 근거 탐색 문서와 2D 흐름 데모가 포함됩니다. 실제 VR 연동·AI 추론 서비스·자동 에이전트 운영은 설계안입니다.

09. 작게 검증하고 확대할 조건

0단계 — 30분 인터뷰: 현재 튜토리얼·사용 기기·첫 조작 문의·수업 일정·로그 여부를 확인합니다. 최근 수업의 실제 장면을 요청하고 해결책에 대한 동의부터 묻지 않습니다.

1단계 — 탐색 관찰: 초보자 6–8명, 교수자·조교 2명 정도를 모집하는 안입니다. 어디서 왜 멈췄는지 확인하기 위한 규모이며 효과를 입증할 표본 수가 아닙니다. 현재 안내로 성공률이 이미 높다면 문제를 재정의합니다.

2단계 — 첫 사용 비교: 현재 안내와 온보딩 패스를 처음 사용하는 참여자에게 각각 배정합니다. 기기·과제·도움 규칙·접근 기회를 맞추고 반복 학습의 순서 효과를 피합니다. 충분한 표본 수는 기초 성공률·탐지할 차이·기관 제약을 확인한 뒤 정합니다. 소규모 탐색 결과에는 인원·분모·불확실성을 함께 표시합니다.

3단계 — 7일 내 후속 실습: 같은 기관에서 두 번째 사용 기회를 실제로 제공합니다. 일정·장비가 제공되지 않은 사람을 이탈 원인과 섞지 않습니다. 7일은 측정 창 제안이며 기관 수업 주기에 맞춰 사전 확정합니다.

사업 가치 계산: 기관별 월 지원 시간 절감 × 시간당 내부 비용 + 추가 운영 가능한 실습의 가치 − 구현·유지·교육 비용. 수업 횟수·가격·계약 갱신 효과를 아직 모르므로 매출이나 ROI를 제시하지 않습니다. 초기에는 기존 고객 활성화·지원 효율 가설로 다루고, 유료 부가 기능 여부는 구매자 인터뷰 뒤 판단합니다.

10. 실무진과 확인할 질문

  1. 지난 수업에서 VR 조작 때문에 멈춘 가장 최근 사례는 무엇이었나요? 화면·손동작·도움 내용을 함께 볼 수 있나요?
  2. 현재 튜토리얼이 이미 해결하는 부분과 해결하지 못하는 부분은 어디인가요?
  3. 2차 사용을 결정하는 것은 학생, 교수자, 수업 일정 중 누구·무엇인가요? 실제 재사용 기회는 얼마나 주어지나요?
  4. 조작 오류·장비 오류·임상 지식 부족을 현장에서 어떻게 구분하나요?
  5. 기기 모델과 기존 엔진에서 point/select/undo 같은 이벤트를 받을 수 있나요?
  6. 도움을 줄일 수 있는 구간과 교육상 반드시 사람이 개입해야 하는 구간은 어디인가요?
  7. 현재 지원 시간과 첫 실습 진입을 측정할 수 없다면, 종이 관찰표부터 시작해도 될까요?
  8. 이 문제보다 먼저 해결해야 할 원인이 확인된다면, 어떤 근거로 우선순위를 바꾸면 좋을까요?

11. 제안하는 첫 협업 범위

실무 인터뷰와 자료 제공이 가능하다는 전제에서, 5영업일 제작 + 7일 후 재사용 관찰을 출발점으로 제안합니다. 참여자 모집·VR 통합·기관 승인 기간은 별도이며 약속된 일정이 아닙니다.

  • 1일차: 현재 흐름 관찰·가설 수정·성공/중단 정의.
  • 2일차: 실제 기기 기준 1분 흐름·안내문·종이 목업.
  • 3일차: 이벤트/완료 기준·예외 흐름·2D 데모.
  • 4일차: 교육·개발 실무 검토·수정.
  • 5일차: 준비된 범위에서 탐색 관찰·실험 계획 고정.
  • 후속: 7일 내 두 번째 실습 기회와 독립 사용 관찰.

제가 먼저 가져갈 것: 근거가 연결된 문제정의 1장, 온보딩 상태·이벤트 표, 2D 데모, 관찰표, 바뀐 판단 기록. 실무팀에 요청할 것: 튜토리얼 체험, 최근 문의 사례, 기기·이벤트 가능 범위, 교육자 검토 1회.

12. 대표님께 전달할 메시지 초안

박선영 대표님, 안녕하세요. 디지털 헬스케어 기획자 오지민입니다.

공유학교 수업에서 학생들이 기기 연결과 위치 찾기에 멈추는 장면을 관찰하고 안내를 바꾼 경험을, 메디크루의 첫 VR 사용에 적용하는 ‘1분 인터랙티브 온보딩 패스’를 정리했습니다. 핵심은 첫 조작을 직접 성공하고 다음 실습에서 스스로 다시 시작할 수 있도록 돕는 것입니다.

제안서에는 영상·제공 자료의 근거 위치와 검증할 가설을 연결했습니다. 아직 제품을 직접 사용하지 않아 현행 튜토리얼과 겹치는 부분, 실제로 조작이 문제가 되는 지점부터 확인하고 싶습니다.

가능하시다면 교육 또는 제품 실무 담당자분과 30분 정도 현재 사용 흐름을 살펴볼 기회를 부탁드립니다. 인터뷰에서는 최근 막힘 사례와 이벤트 수집 가능 범위를 확인하고, 그 결과를 한 장의 흐름도와 작은 검증안으로 구체화하겠습니다.

감사합니다. 오지민 드림.
